(2026-07-11). Purpose: give a future builder the exact testable surface and the
fixes already made, so they extend rather than re-debug.

## Test recipe (copy this shape)
File: `backend/tests/test_reverse_engineering.py` (D3D01, 30 passed / 0 failed).
- Write a synthetic gcode string to `tmp_path` (use Orca-style comments:
  `;layer_height = 0.2`, `;nozzle_temperature = 210`, `;bed_temperature = 60`,
  `;wall_loops = 3`, `;acceleration = 2000`, `;filament_type = PLA`,
  `;total_layers = 100`, plus a few `G1 X.. Y.. Z..` moves for the bounding box
  and a `T0`/`T1` for extruders). Assert `decompile_gcode` recovers each field.
- Assert bounding box from G1 moves: `size_x`, `size_y`, `size_z`, `x_min`…
- `geometry_to_stl` facet counts: box = 12, cylinder (24 segments) = 96.
- `_parse_diagnosis`: fenced ```json …```, embedded JSON, and garbage →
  `failure_type == "unknown"`, `confidence == 0`.
- `quality_rules`: build `GcodeSettings(...)` by hand; assert rules fire per
  material (PLA bed<50 → `bed_temp_low`; ABS + fan → `fan_warm_material`;
  accel>8000 → `accel_critical`; infill 0 / walls 0; missing temps); assert
  `score()` in [0,100]; assert `recommended_calibrations()` dedups.

Run: `cd backend/tests && source ../.venv/bin/activate && python -m pytest test_reverse_engineering.py -v`

## Bugs found + fixed this session (do NOT re-open unless regression)
1. **`_set_field` truncated fractional floats.** Root cause: `GcodeSettings`
   fields like `layer_height: float = 0` have an *int* runtime default, so the old
   `isinstance(current, int)` branch ran `int(float("0.2")) == 0`. Affected
   layer_height, first_layer_height, pressure_advance, filament_used_mm, etc.
   Fix: coerce by `__dataclass_fields__[name].type` (float vs int). Verified
   (0.2, 0.04, 1234.5 now parse correctly).
2. **`failure_diagnosis` enrichment never fired.** `FAILURE_TO_CALIBRATION`
   keys use hyphens (`under-extrusion`) but only the diagnosis side was
   normalised (hyphen→underscore), so `key in failure_lower` was always False.
   Fix: normalise BOTH sides before the substring match.
3. **slicer detection missed `; generated by X`.** Real slicers emit
   `; generated by OrcaSlicer-2.0` (no `=`/`:`). Added the additive pattern
   `;generated\s+by\s+(.+)`. Captured value is lowercased (matches the module's
   line-lowercasing); expect lowercase in assertions.

## Note on captured values
`gcode_decompile` lowercases each line before regex match, so string captures
(`filament_type`, `slicer`, `material`) come back LOWERCASE. `quality_rules`
resolves material with `.upper()`, so passing decompiled settings works. In
tests, assert lowercased (e.g. `"pla"`, `"orcaslicer-2.0"`). Float fields now
keep their decimals (post-fix #1).
