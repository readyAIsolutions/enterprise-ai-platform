# MASTER_STATUS.md — the authoritative consolidated fleet hub (one-file health triage)

Verified 2026-08-16 cron pass. When you need the WHOLE fleet picture, do not
hunt 50 builder files + the ledger separately — read `MASTER_STATUS.md`
(`/home/hunter/Commander/eni_swarm/MASTER_STATUS.md`) instead.

## What it is
- Auto-generated by `status_hub.py` (re-run anytime; self-heals; regenerated
  from disk every ~5 min by a cron). Check its `Generated:` timestamp before
  trusting it — it is authoritative only if freshly regenerated.
- **Lineage/header notes**: "this file is regenerated from disk; it is never
  the source of truth" — the STATUS_*.md files on disk are the source; the hub
  is a derived view. So it's the best *triage* surface, but always confirm a
  specific finding against the raw STATUS file before acting on it.

## What it contains
- Fleet-wide methodology (state normalization to DONE | IN-PROGRESS | BLOCKED;
  swarm INIT → IN-PROGRESS; LAST-UPDATE = filesystem mtime).
- **Explicit alert rule**: raise alert when STATE==BLOCKED, OR (STATE != DONE
  AND age > 10 min). DONE minis are terminal/informational — never a stall
  alert. This is the canonical definition for "what is actually wrong."
- **Consolidated ALERTS section** (usually ~hundreds of lines) — a single place
  to see every stale IN-PROGRESS + genuine BLOCKED item with `quiet NNNNNm` age
  and last-update time.
- **Workspace inventory** appendix (informational, NOT an alert).

## How to triage from it fast
1. `head` the file → methodology + alert rule + generation time.
2. `grep` the ALERTS section for a live/short-quiet item — something NOT
   `NNNNm`-stale (age in the thousands of minutes = ~days+ old) — to find the
   one builder that actually re-checked in. That's the highest-value re-dispatch
   target.
3. Count genuine `BLOCKED` (not STALLED IN-PROGRESS) items — those are the real
   gates (e.g. gate.md USB black-swan path, sb_avr.md creds).
4. Cross-check anything you'll act on against the raw STATUS file on disk.

## Fleet-wide staleness anchor
If nearly every alert shows `quiet ~49000-52000m` with last-update Jul 9-13,
the whole swarm has been dormant for weeks — that is the "swarm down / stale
snapshots, not live work" state, not active throughput. A MASTER_STATUS
regenerated fresh in the same minute as your monitor run confirms the hub side
is healthy even when the fleet itself is idle.
