# Headless ENI floor — crash recovery (gen_floor_opt.sh / swarm_start_opt.sh)

## Topology (the surviving design on LO's box)
- Headless builders, NO xfce4-terminal PTY tax. 54 builders total:
  SB=12, D3D=18, NAS=12, LUM=12 (D3D weighted heaviest).
- Run scripts:  /tmp/eni_opt/run_<NAME>.sh   (regenerated by gen_floor_opt.sh)
- Dashboards:   /tmp/eni_opt/dash_<KEY>.sh  (4, one per product)
- Config:       ~/Desktop/Commander/eni_swarm/swarm_products.cfg
- Lock file:    /tmp/eni_opt.lock  (flock held by the swarm_start_opt.sh parent)
- Each builder is `bash run_<NAME>.sh` which loops `while true; sleep 8` and
  re-execs `python3 eni_agent_term.py ...` — so a dead builder respawns
  on its own once the launch cause is fixed.

## Recover entry point
`bash ~/Desktop/Commander/eni_swarm/swarm_start_opt.sh`
- Idempotent: regenerates run scripts, launches only MISSING builders (skips
  alive by name), starts mem_sentinel + healer. Safe to re-run.
- If it prints `already booting (lock held) — exiting`, a STALE lock holder
  is keeping the flock open (Bug A). Free it, then re-run.

## Symptom -> cause map
- `pgrep -fc eni_agent_term.py` == 0 but wrappers (`pgrep -fc 'run_.*\.sh'`)
  are alive -> the python child dies on launch. Read the builder log:
  `tail /tmp/eni_opt_logs/<NAME>.log`.
- `BlockingIOError: [Errno 11] Resource temporarily unavailable` at
  `pty.fork()/os.fork()` -> LOOKS like an OOM/nproc wall, but on this
  box (123k nproc ceiling, ~27 GB free) it is almost always STALE log from a
  previous run. Do NOT over-fit on it. Look for the SECOND, distinct error.
- `nice: : No such file or directory (os error 2)` -> the LIVE bug: the
  generated run script's command is EMPTY (`nice -n 5 ""`). See Bug B.
  Once you see this line, the "fork EAGAIN" above is a red herring.

## Bug A — flock fd inherited by children (lock never frees)
swarm_start_opt.sh does `exec 9>/tmp/eni_opt.lock; flock -n 9` then launches
builders with `nohup bash "$OD/run_${name}.sh" &`. The child INHERITS the
open fd 9, so it holds the flock even after the parent exits. Every wrapper
inherits it -> the lock is held FOREVER -> every later `swarm_start_opt.sh`
prints "already booting" and bails.
FIX (in swarm_start_opt.sh): close fd 9 for the child:
  - nohup bash "$OD/run_${name}.sh" >/dev/null 2>&1 9<&- &
  - nohup bash "$ROOT/mem_sentinel_opt.sh" >/tmp/eni_opt_sentinel.log 2>&1 9<&- &
  - same for swarm_healer.sh if present.

## Bug B — heredoc `${CMD[@]}` expands to EMPTY at write-time
In gen_floor_opt.sh `gen_run`, the line
  `  ( ulimit -v ...; ulimit -u ...; nice -n 5 "${CMD[@]}" ) >> ...`
sits inside an UNQUOTED heredoc (`<<RUNEOF`). At write-time gen_run has NO
`CMD` array in scope — the `CMD=(python3 ...)` definition is only TEXT written
INTO the generated run script (executed later, at the generated script's
runtime, on the line ABOVE the nice line). So `${CMD[@]}` expands to EMPTY ->
generated script = `nice -n 5 ""`.
FIX: escape it so it survives literally into the generated script and is
evaluated at the generated script's runtime (after CMD is defined):
  -  ( ulimit -v 12000000 2>/dev/null; ulimit -u 600 2>/dev/null; nice -n 5 "\${CMD[@]}" ) >> "$LOGD/$name.log" 2>&1
(While there: raise `ulimit -v` from 2200000 (2.2 GB) to ~12000000 (12 GB) —
hermes+python legitimately maps >2.2 GB VIRT after a few minutes of a build
session, so the 2.2 GB cap alone can also cause fork EAGAIN. The
mem_sentinel already guards real RSS/OOM, so a higher VIRT cap is safe.)
VERIFY the fix by reading the generated artifact:
  sed -n '14p' /tmp/eni_opt/run_D3D1.sh
  -> must show:  nice -n 5 "${CMD[@]}"   (literal, NOT empty "")

## Recovery recipe
1. Free any stale lock holder (kill by fd, NOT by name — see pkill note):
   holders=$(fuser /tmp/eni_opt.lock 2>/dev/null | tr ' ' '\n' | grep -v '^$')
   [ -n "$holders" ] && { kill -9 $holders; sleep 2; }
2. Regenerate run scripts:  bash gen_floor_opt.sh
3. (Optional) Clear stale logs for a clean signal:
   find /tmp/eni_opt_logs -name '*.log' -exec truncate -s 0 {} \;
4. Relaunch:               bash swarm_start_opt.sh
5. Wait ~20s (builders stagger-sleep up to ~53s before first launch), then:
   pgrep -fc 'eni_agent_ter[m].py'   -> should climb toward 54
   tail /tmp/eni_opt_logs/D3D1.log    -> must show the hermes REPL banner,
                                       NOT "No such file" / empty cmd

## pkill self-kill (bit us twice this session)
`pkill -f 'pattern'` matches /proc/<pid>/cmdline, and YOUR OWN shell's
cmdline CONTAINS the command text — so a pattern that also appears in your
command (e.g. `pkill -f 'eni_agent_term[.]py'`) matches and SIGTERMs your
own shell (exit -15, empty/truncated log). AVOID by:
  - Putting the recovery in a SCRIPT FILE (its argv is `bash recover.sh`,
    which does NOT contain the regexes), or
  - Killing by lock-holder via `fuser` (above), or
  - Crafting self-unsafe patterns, e.g. `eni_opt/ru[n]_` matches the
    wrapper `run_SB1.sh` but NOT your own cmdline text `ru[n]_`.
