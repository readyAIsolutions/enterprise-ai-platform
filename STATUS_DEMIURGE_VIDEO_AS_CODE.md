## Concept (grounded in the transcript)

The speaker treats AI video/animation generation as **software engineering
applied to a creative problem**. The **hard work is not the AI and not the
code — it is the spec** (a markdown "brief"). A **loose spec makes the AI agent
make more interpretive choices or hallucinate more**; a tight spec directs it
"at every beat". Motivating quote (attributed to David Ugarte):
> *"Give me the freedom of a tight brief."*

The stack described: **spec (markdown brief) -> coding agent (Claude Code) ->
Remotion component library -> video editing software (Cap Cut)**. Each scene is
a React component ("a video is just a function of images over time"); reusable
building blocks (text animations, backgrounds, transitions, data
visualizations) are assembled per the spec.

### What the module implements
- `VideoSpec` / `Scene` structured brief model (title, thesis, arc, per-scene
  description, timing, visual elements, emphasis, background notes, script).
- `parse_spec_markdown` parses a brief; `spec_to_dict`/`spec_from_dict`
  JSON round-trip.
- `validate_spec` — warns on missing/loose fields (the "loose spec" signals).
- `tightness_score` → `[0,1]` (weighted structuredness: metadata, structure,
  scene detail, timing, script).
- `hallucination_risk_estimate(tightness) = clamp(1 - tightness)` — **inverse
  to tightness**, per the transcript claim.
- `PipelineRunner` — spec → (injectable deterministic `StubGenerator`) →
  `AssemblyManifest` → artifact `manifest.json`. `RealGenerator` **degrades
  gracefully** (`ok: False`) when no tooling is available (network-free).
- Registered Platform Kernel module `VideoAsCodeModule` with lifecycle
  `initialize` / `health_check` / `shutdown`, `set_event_bus`, and event
  publishing only when an event bus is wired.

## UNVALIDATED (known limitations)

- **Hallucination-risk numbers are a documented heuristic**, not a measured
  quantity — there is no live AI to empirically validate the risk↔tightness
  mapping (network-free module).
- **`parse_spec_markdown`** is a pragmatic parser for the speaker's spec shape
  (headings + `Field:` lines + bullet lists); non-conforming markdown briefs
  are tolerated (missing fields surface via `validate_spec`) but not fully
  normalized.
- **`RealGenerator`** has no real external tooling attached (network-free);
  live integration with Claude Code / Remotion is **out of scope / TODO**.
- No cross-module integration or full-suite regression run was performed (the
  full test suite was intentionally **not** run; other modules, `config.yaml`,
  `platform_kernel.py`, and `data/build/manifest.json` were not touched).
