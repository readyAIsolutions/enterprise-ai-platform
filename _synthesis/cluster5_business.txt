PART 4 — SECRET ARCHITECTURE (HOW SECRETS NEVER LEAVE THE MACHINE)
--------------------------------------------------------------------
Principle (dirname/section header commit): ALL secrets, API keys, credentials,
PII and sensitive env vars are handled EXCLUSIVELY by LOCAL models. Cloud models
NEVER receive real secrets — only sanitized prompts with placeholders.

CORE FLOW (per LOCAL_FIRST_SECRET_ARCHITECTURE.md):
  User request -> PROMPT GUARD (injection/jailbreak/policy detect; violation => BLOCK+AUDIT)
    -> SECRET DETECTOR (regex API-key patterns + entropy analysis on base64 +
       PII patterns email/phone/SSN + private-key headers + custom config patterns)
      -> secrets found? NO  => MODEL ROUTER direct
         secrets found? YES => SECRET BROKER substitutes each secret with a token
            like {SECRET:OPENAI_API_KEY}, {PII:EMAIL:user@d}}, {CRED:AWS_...}
            -> LOCAL MODEL ONLY (llama.cpp/Ollama)
    LOCAL MODEL: binds to 127.0.0.1 ONLY; NO network egress; NO filesystem access
      beyond config; receives placeholder prompt; returns placeholder response.
    If local model is down and a request contains real secrets => BLOCK (hard
      error, NEVER send to cloud). This is a hard, non-configurable rule.
  CLOUD MODELS: receive ONLY the sanitized placeholder prompt; placeholders remain
    in the response; they never see a real key.
  REVERSE SUBSTITUTION: after the response returns, the Secret Broker re-substitutes
    real values back IN MEMORY ONLY — never written to disk or logs.
  OUTPUT VALIDATOR: checks merged response for secret leakage, exfiltration
    encoding patterns, refusal, toxicity, policy compliance; violation => block+audit.
  AUDIT LOGGER: hash-chained (SHA-256 chain H(n)=H(H(n-1)+ts+event)), append-only,
    tamper-evident, immutable.

KEY GUIDING ROUTING RULES (hard-coded, not configurable):
    Any request, HAS secrets  => LOCAL ONLY, fallback = BLOCK
    Code gen, no secrets       => Local preferred -> Cloud fallback
    Analysis/reasoning, no secrets -> Local -> Cloud
    Creative writing, no secrets -> Cloud (better quality), fallback Local
    Embeddings, no secrets         -> Local (all-MiniLM), fallback Cloud
    Image gen, no secrets         -> Cloud only

COMPONENTS / SPECS:
  - SecretBroker (secret_broker.py): encrypted secret store AES-256-GCM (or age/rage/
    Fernet), secret detection (regex+entropy), forward+reverse substitution, audit
    log for every secret access, local-model endpoint mgmt. Secret store file
    ~/.hermes/secrets.enc, encrypted with master key derived from user passphrase +
    hardware ID. Store metadata sets created/last_accessed/access_count.
  - ModelRouter: enforces the "SECRETS -> LOCAL ONLY" hard rule, health checks,
    fallback (local down + secrets = BLOCK), cloud load-balancing, providor
    transform, identity verified via health checks.
  - PromptGuard: injection (direct/indirect, delimiters, encoding tricks,
    context-leak) + jailbreak (role-play, hypothetical, translation, prompt leak)
    pattern libraries w/ confidence via best scoring; confidence in threshing
    default 0.7. Example checked: special "repeat your prompt", "decode base64...".

  - OutputValidator: exfiltration detection, refusal detection, toxicity, policy.
  - AuditLogger: hash-chained append-only log.
  - RateLimiter: token-bucket per user/IP/endpoint/model (60 rpm, burst 10, per-user 100).
  - SandboxEnforcer: tool allowlist, arg validation, isolation.
  - PolicyEngine: YAML declarative policies (allow/deny/transform) evaluated at
    inference time; sample policy: contains_secret AND target_model.is_cloud
    => action block, reason "Secrets must never leave local infrastructure".
  - Priority 0 module, REQUIRED: model_security initializes FIRST before ANY other
    module; the platform FAILS to boot unless security initializes; shuts down last.

THREAT MODEL (defense even if a model is FULLY compromised):
  T1 Cloud model compromised: impossible for it to extract secrets (it never
    receives them); encoding exfiltration caught by OutputValidator; no tool
    access for cloud model; DoS mitigated by rate limit + local backup.
  T2 Local model compromised: isolated process, no FS access, bind 127.0.0.1 no
    egress, secrets in-process memory only, mlock if available, signature/repro
    builds verify weights. Residual: build-time compromise.
  T3 Hermes process compromised: secrets encrypted at rest, decrypted only
    briefly, zeroed after; placeholder map in function scope only, never
    persisted; tamper-evident audit chain.
  T4 Supply chain: zero external deps on the security-critical path (stdlib),
    signature verifier (sigstore/cosign), SBOM (CycloneDX), reproducible builds.
  RESILIENT-TO-USE SUMMARY: This is an INFRASTRUCTURE-layer security approach:
    security sits in the infrastructure BETWEEN caller and model, so it holds
    even if every model is itself compromised.

PART 6 — SETUP INSTALL STEPS (setup.sh, one-command installer)
--------------------------------------------------------------------
A ./setup.sh "make setup easy" one-command boot. Modes:
  bash setup.sh            interactive full setup
  bash setup.sh --yes      non-interactive / CI (no prompts)
  bash setup.sh --bare     install deps + verify only, don't start services
  bash setup.sh --no-pack  skip skillspack deploy

Steps (idempotent):
  1. cd to enterprise repo root; sanity-check it sees platform_kernel.py
     (either enterprise/platform_kernel.py or ./platform_kernel.py); sets PYTHONPATH=$ROOT.
  2. [1/6] Install Python deps from enterprise/requirements.txt, prefer an
     existing env; if system pip is unavailable/externally-managed, create a
     local .venv; if pip install fails, core platform is stdlib-only so still works.
  3. [2/6] Deploy the portable skills/LSP/MCP/plugin pack via
     enterprise/scripts/install_skillspack.sh (non-fatal warnings allowed; skippable).
  4. [3/6] Install + enable systemd user services: eni-controller + eni-multiplayer-server
     (via eni_cli setup logic; skip with --bare or if no systemd user dir).
  5. [4/6] Verify the platform kernel imports.
  6. [5/6] Show platform status via eni_cli status.
  7. [6/6] Done. Print endpoints:
      - demo: curl -X POST http://127.0.0.1:8788/api/submit_plan -d '{"goal":"build a to-do app","tenant":"acme"}'
      - dashboard: http://127.0.0.1:8788/api/board  (also :8420 per other docs)
      - brain/heartbeat: http://127.0.0.1:8913/health
      - boot servers: bash enterprise/scripts/boot_all.sh
      - CLI: python3 enterprise/scripts/eni_cli status

  README quick-links also list: API gateway :8421, Swarm Dashboard :8420, Agent
  Server :9120, Swarm Turbocharger /8922/health, Free Model Router /8920/health.
  Build: cd "Eni Builder"; python3 -m pytest enterprise/ -q -p no:anyio; start
  with uvicorn enterprise.integration.api_gateway; docker-compose up -d.
